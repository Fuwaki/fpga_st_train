# v4 — 更低比特：4bit / 2bit

日期 2026-09-13 · 承接 `v3-int8-qat.md`。
v3 把模型做到了 int8；这一版把量化器泛化成任意位宽，量一下"还能往下压多少"。

画廊：`runs/gallery/index.html`（总览 `overview.png`，逐图 `animal.png` … `water.png`）。

---

## 1. 改了什么

量化器从"写死 int8"改成 `Bits { acts, weights }`，激活和权重可以各自定位宽：

```bash
# 标定时指定位宽，QAT / 模拟 / 导出都从这份 JSON 读
fpga_st_train calibrate --act-bits 4 --weight-bits 4 ... --out scales-w4a4.json
fpga_st_train train --config <quant.calibration = scales-w4a4.json>
fpga_st_train student-stylize --quant scales-w4a4.json     # 定点模拟
fpga_st_train export-int8 --calibration scales-w4a4.json   # 导出
```

按 **`WnAm`** 记：n 比特权重 / m 比特激活。

**测试协议**（两个数分开算，这点很重要）：

- **量化保真度**：量化后的输出 vs **同一个模型自己**的 fp32 输出。这是"量化本身损失了多少"。
- **端到端**：量化后的输出 vs 最初 v2-lr6 的 fp32 输出。这是"最终交付的东西长什么样"。
  QAT 会顺带继续训练，所以端到端数字里混了"模型变了"和"量化变差了"两件事，不能单独用来评价量化。

## 2. 结果

参考模型：`runs/v2-lr6/final.mpk`（定稿的 fp32 学生）。6 张 demo 图，384 长边。

### 量化保真度（最重要的一张表）

| 方案 | PTQ | QAT |
|---|---|---|
| W8A8 | 48.44 dB | 49.37 dB |
| W4A8 | 41.59 dB | 41.22 dB |
| W8A4 | 26.28 dB | — |
| W4A4 | 27.25 dB | **32.47 dB** |
| W2A8 | 21.34 dB | **25.38 dB** |
| W2A4 | 22.06 dB | — |
| W2A2 | 11.98 dB | 2.58 dB（崩了） |

QAT 设置统一为：从 v2-lr6 热启动、冻结激活 scale、lr 8e-5 线性降到 8e-6、1200 步。

### 端到端（交付视角）

| 方案 | PTQ | QAT |
|---|---|---|
| W8A8 | 48.44 dB | (v3 的 QAT 模型 38.57 dB) |
| W4A8 | 41.59 dB | 39.29 dB |
| W4A4 | 27.25 dB | 32.76 dB |
| W2A8 | 21.34 dB | 33.38 dB |
| W2A2 | 11.98 dB | 17.93 dB |

## 3. 结论

**① 4bit 权重几乎不要钱，4bit 激活非常贵。**

W8A8 → W4A8 只掉 6.9 dB，而 W8A8 → W8A4 掉 22 dB。
到了 W4A8 这个组合，权重已经占多少便宜都无所谓了：**W4A4（27.25）甚至比 W8A4（26.28）更好**。
这个"更粗反而更好"不是噪声——重跑两次数字完全一致。
原因是量化误差不独立：激活网格是主要误差源，权重误差换个方向反而把更多值推到了激活网格的正点上。
结论就是 **A4 下权重的精度已经不是瓶颈，再给权重加位是浪费**。

**② 激活是瓶颈，而且不是离群值造成的。**

直觉上 4bit 激活差是因为少数大值撑大了 per-tensor scale，砍掉它们（`--safety < 1`）应该有帮助。
实测**没有**：

| A4 safety | 1.0 | 0.5 | 0.35 | 0.25 |
|---|---|---|---|---|
| W8A4 | **26.68** | 28.26* | 23.97 | 20.27 |

（*这一行是在 QAT 模型上量的，行内可比；s0.5 看起来略好，但 A8 上同样操作会从 48.8 掉到 29.9，
说明收窄范围整体是亏的。）

也就是说误差是**均匀**的、不是离群值主导的，靠调阈值救不回来。这正是 QAT 的用武之地。

**③ QAT 在 4bit 上值 +5.6 dB。** W4A4 从 27.25 提到 32.47。但 W4A8 上它没用（41.59 → 41.22），
因为那里本来就没什么损失可捡。**QAT 的收益和 PTQ 的损失成正比**，这条在 v3 和这里是一致的。

**④ W2A2 会崩。** 1200 步后 loss 停在 0.18（基线 0.05），量化保真度反而从 11.98 掉到 2.58。
2bit 激活（每张量只有 3 个电平）+ 三值权重，这个组合超出了当前方案的能力，别用。

**⑤ 推荐的甜点：W4A8。** 权重存储直接省一半（相对 int8 是 4x），保真度 41.6 dB，QAT 后 41.2 dB，
端到端 39.3 dB。配 v3 那套每通道权重 scale，硬件上不需要改动。

## 4. 一个没做成的尝试（记下来）

动过一个念头：网络里 **16 个量化点全都是非负的**（要么是 [0,1] 的原图，要么是 ReLU 输出，
要么是两个非负张量相加），那对称量化就白白浪费了一半码本——4bit 对称在 [0, A] 上其实只有 8 个电平，
改成 **uint4 就能拿到 16 个电平，等于多一位**（用对称 A5 做了代理验证：A4 26.28 → A5 32.83，确实值一位）。

我把激活改成了无符号，同时补上了模拟里一直漏掉的最后一级 uint8 输出量化。
结果量化保真度反而从 48.44 掉到 31.98 dB，而且掉的方式不对：输出被**压缩**了
（fp32 范围 [0.086, 0.553] → 模拟 [0.129, 0.506]，均值偏 +0.013），是增益/直流偏移错误，不是量化噪声。

**没查完就停了**（用户要求先出画廊），所以已经**回退到验证过的对称路径**，
当前代码里 `Bits::act_max()`、`fake_quant_act`、`fake_quant_output` 都有注释说明这件事。
下一步排查方向：先确认是不是输出量化那一步引入的（单独关掉 `fake_quant_output` 复测），
再单独验证无符号激活。**在查清楚之前不要相信任何 uint 激活的数字。**

（顺带发现一个真问题：模拟里一直没有建模最后的 uint8 输出量化，
而导出的 manifest 里 head 的输出会被 clamp 到 [0,255]，也就是 0.498 以上的高光会被削掉。
v3 报的 48.80 dB 因此偏乐观。要修。）

## 5. 下一步

1. **先修上面那个 uint 激活的问题**，它值整整一位，是所有方向里最便宜的一个。
2. **2bit 权重想要能用，得改成分组 scale**（比如每 32 个权重共用一个 scale，GPTQ/AWQ 那套）。
   现在每通道一个 scale，三值权重太粗。
3. 把 `--safety` 换成**从直方图算 MSE 最优阈值**（现在只能人肉扫几个点）。
4. 导出支持 4bit 打包（现在 `weights.bin` 还是一个 code 一字节，4bit 实际可以压到 184 KiB）。
